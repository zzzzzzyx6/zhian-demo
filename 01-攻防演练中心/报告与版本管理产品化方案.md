# 报告与版本管理产品化方案

> 版本管理部分已被用户后续决定替代：不纳入未演练连接，不做手动对比，改为靶标任务驱动的模型结果与同方案得分排名。当前实现见《题库与版本结果更新说明.md》。报告部分仍保留为设计参考。

日期：2026-09-28。本文只提出产品方案；本轮保留现有报告实现，不修改报告或版本管理的 JS/CSS。

## 一、设计结论

任务概览用于快速了解本次任务，正式报告用于解释本次结果并支撑后续处置。两者使用同一份任务快照和统计口径，但信息深度不同，不能把几块统计卡片重复一遍就作为报告。

版本管理应首先是一份完整的模型版本清单。用户先看到全部已接入对象，再自主选出 2—4 个对象、明确选用哪次演练，点击「开始对比」后查看结果。没有演练记录的对象仍然存在于清单中，不应因为没有结果而消失。

当前可以做可靠的执行统计、具体攻击方法分析、攻破记录复核、已有题目分类覆盖分析。没有题目分类、判定依据或可比运行时，直接展示缺口；不推导具体违法犯罪场景、统一安全等级、已确认漏洞或修复效果。

## 二、现状核实

### 2.1 报告已有的数据基础

| 数据 | 当前可用情况 | 可以支撑的表达 |
| --- | --- | --- |
| 测试单元 `units` | 有具体 `method`、结果、题目关联 | 已执行／待判定、有效判定、攻破／守住／异常、按具体方法统计 ASR |
| 题目 `questionId` | 新任务有题库快照关联，历史或异常数据可能缺失 | 按题目去重；缺失时明确无法完整去重 |
| 题目 `category` | 可选字段；AdvBench 520 题无分类，SALAD 子集 1000 题已有 66 个原始细分类别 | 已有原始分类的覆盖及攻破分布；未分类单列 |
| 输入、响应与裁判结果 | 有攻击输入、响应、`verdict`；多轮任务保留 `roundHistory` | 查看攻破过程和最终交付内容，复核该条判定 |
| 任务配置快照 | 有题库、靶标、红队、蓝队、裁判、方法及部分参数 | 说明本轮测了什么、如何测；判断两次演练已记录的配置是否一致 |
| 人工复核、违规规则、严重度 | 尚无统一结构化字段 | 不能直接写“已确认漏洞”“高危问题”或统一安全评级 |

这里的“有数据依据”指现有任务里实际记录的字段，不代表已经完成真实模型测试。当前执行器生成模拟结果，页面和导出的报告都需要保留「模拟数据」标识。

`src/report-insights.js` 已集中完成统计和渲染：`X.taskAnalysis` 在第 14 行，报告正文拼装在第 126 行，报告页面和导出在第 127、132 行。现有结构已包含方法表现、证据、分类缺口和结论边界，可作为后续正式报告的基础，不必推翻。

### 2.2 版本管理为何仍有“预设感”

当前版本页已从固定图表改为读取任务数据，但交互仍替用户做了许多选择：

| 当前行为 | 代码位置 | 用户感受 |
| --- | --- | --- |
| 只从已有任务生成系列和版本 | `src/model-series.js:12`、`:17` | 没做过演练的已接入模型不存在，像演示案例清单 |
| 自动选择第一个匹配系列 | `src/model-series.js:25` | 进页后就被限定在一个系列，而非完整清单 |
| 默认勾选前 4 个版本 | `src/model-series.js:37` | 对比对象好像已经被预设，选择目的不清楚 |
| 自动挑已完成任务，否则挑最近任务 | `src/model-series.js:32` | 不容易看出每列指标到底取自哪次、什么条件的演练 |
| 勾选即显示对比结果，没有明确开始动作 | `src/model-series.js:42`、`:72` | 勾选清单与正式对比没有阶段边界 |
| 同版本对比自动拿最近 4 次演练 | `src/model-series.js:49` | 同样缺少对运行记录的自主选择 |
| 最近几次有有效结果的演练直接连接成趋势 | `src/model-series.js:51` | 题库、方法或防守配置改变，也可能看起来像版本能力提升 |
| 配置比较只是折叠展示名称 | `src/model-series.js:62` | 没有告诉用户结果能否直接比较、哪些条件不同 |

另外，连接资产与版本身份尚未真正分离。连接保存在 `X.db.models`，系列／版本主要保存在任务的 `targetMeta`；连接保存字段没有独立版本档案（`src/attack-setup.js:87`），版本身份部分来自名称推断和历史任务（`src/workflow-coordination.js:12`）。因此只换布局还不够，需要把“已接入对象”作为清单底座。

## 三、任务概览与正式报告

### 3.1 两个页面各自回答什么

| 页面 | 用户的问题 | 推荐内容 |
| --- | --- | --- |
| 任务概览 | 跑到哪里了？现在主要发现什么？下一步做什么？ | 一行核心数据、最多 2 条核心发现、1 个明确行动入口；执行过程仍在演练视图 |
| 演练报告 | 这次结果说明什么？依据是什么？范围和不足在哪里？ | 完整范围、结论、方法分析、证据、建议、覆盖缺口与统计口径 |
| 攻防记录 | 某条结果究竟怎么来的？ | 原题、攻击输入、多轮过程、最终响应、裁判依据、异常信息 |

任务名称后保留状态，攻防配置放在任务名称下面。正式报告 tab 应有明确的报告标题和导出入口；后续布局调整时，不再在报告正文上方完整重复任务概览的大段发现和建议。报告摘要可以复述关键结论，但必须进一步给出范围、证据和依据。

概览推荐保留：已执行／计划、ASR、攻破、守住、涉及攻破题目、异常。ASR 的辅助说明显示有效判定数；缺少题目 ID 时，“涉及题目”不输出伪精确总数。这里的“涉及题目”不是已确认风险个数。

### 3.2 正式报告的信息顺序

正式报告使用单一纵向阅读结构。页面内可提供轻量目录定位章节；避免每章都用大数字卡片和重复图表。

| 章节 | 需要呈现的内容 | 交互或证据入口 |
| --- | --- | --- |
| 报告摘要 | 报告名称、任务状态、生成时间、模拟／真实执行标识；关键结果、最主要发现、当前结论范围 | 报告导出 |
| 1. 评估范围与方法 | 靶标版本、题库与实际题目范围、具体攻击方法、蓝队配置、红队和裁判版本、关键执行参数 | 查看完整配置快照 |
| 2. 结果与核心发现 | 已执行／计划、有效判定、攻破／守住／异常；2—3 条与本轮数据对应的发现 | 定位到方法分析或证据条目 |
| 3. 攻击方法分析 | 各具体方法的样本量、有效判定、攻破／守住、ASR、异常；必要时展示分布条形图 | 点击方法，筛选该方法的记录 |
| 4. 重点攻破证据 | 原题、具体方法、最终响应、裁判依据；多次攻破同题时可在同一题目下组织记录 | 打开完整攻击过程 |
| 5. 后续建议 | 每项建议对应哪条发现／证据、需要做什么、完成后如何验证 | 查看关联记录、按原配置准备复测 |
| 6. 覆盖缺口与附录 | 未执行、异常、待分类、缺少题目关联、证据未保存；统计口径和完整记录索引 | 筛选缺口记录或进入题库完善信息 |

“正式”体现在结构完整、结论可追溯、导出后能够独立阅读，不取决于图表数量。当前没有业务场景标签时，第 3 章就叫「攻击方法分析」，不改名为「违法犯罪风险分析」或「场景安全画像」。

### 3.3 核心发现要从事实走到可执行动作

采用“观察到的事实 → 相关证据 → 建议动作”三段结构。下面是文案模板，数字必须实时取自任务，不能写死：

| 有依据的发现 | 下一步建议 | 不应扩展成的结论 |
| --- | --- | --- |
| PAIR 产生 N 条攻破记录，涉及 M 道题 | 复核对应最终响应与裁判依据，确认后的记录纳入回归集 | “PAIR 是最强攻击方法”或“模型有 M 个高危漏洞” |
| N 条执行异常，导致部分单元无有效判定 | 检查实际异常原因，按原配置补测 | “防护失效”或直接把异常计为攻破 |
| 某原始分类有 N 道已有效判定题目，其中 M 道出现攻破 | 查看该分类的实际题目与证据，再决定策略调整 | 仅凭题目类别就认定业务已发生该类风险 |
| N 道题无分类 | 为这些题目补齐分类和标注依据，再开展分类分析 | 从题目标题或攻击方法猜出风险分类 |
| 已有效判定 N 个单元暂未攻破 | 保留本轮配置与结果，补齐未测范围 | “模型安全”“已经修复”或“零风险” |

相同题目由多种方法反复攻破时，应同时显示“攻破记录数”和“涉及题目数”。缺少人工复核字段时使用「待复核攻破记录」，不使用「已确认风险」。现有裁判结论如果只是泛化文字，报告需要说明证据深度不足，不能自动补写具体违规原因。

### 3.4 建议分两类，避免泛化业务建议

第一类是当前可以立即给出的动作：复核攻破记录、排查异常、补齐剩余测试单元、补充题目分类、固定题库与配置后复测。这些动作均能关联本轮数据。

第二类是需要额外证据才给出的修复建议：调整系统提示词、补充输入／输出护栏规则、改变业务授权逻辑。只有当具体失败证据和违规规则支持时才呈现；不能在每份报告中默认输出“加强权限控制”等固定建议。

下一阶段若要提升报告质量，优先补充：题目标准分类和判定规则、具体命中的响应片段、人工复核状态。后续才增加严重度与处置责任人。不要为了报告看起来丰富而先做没有依据的评级或趋势。

### 3.5 导出与异常状态

页面和 HTML／PDF／Word 兼容导出使用同一份分析结果和记录快照；导出的正式报告包含完整范围、统计口径及证据索引，不依赖网页里的按钮才能理解。

页面可只展示少量重点证据并提供完整记录入口，导出需要明确“重点证据节选”，并附完整攻破记录索引或附录。现有导出仍取前三条证据，应在下一轮正式报告建设时补齐这一点，不能把节选冒充完整报告证据。

进行中／暂停／提前结束任务使用「阶段报告」，写清已完成范围。全异常时只输出执行情况与补测建议，ASR 为 `--`；没有单元或没有有效判定时，不生成积极或消极的安全结论。大段技术口径放在最后，摘要只保留会影响用户判断的缺口。

## 四、版本管理：从完整清单开始

### 4.1 首页为平铺清单，初始零选中

默认展示模型管理中全部已接入模型／智能体版本，跨系列平铺，不自动进入 Qwen 等某个系列。未进行演练的对象同样显示。红队／裁判用途、被测用途通过标签和筛选区分，不能因为暂时没有被测记录而隐藏资产。未完成配置的预置连接不冒充“已接入模型”，以「待配置」区分。

首屏推荐使用表格，便于批量筛选和选择；卡片上的小趋势默认取消。一个模型只有一次运行，或多次运行条件不同，不画连续趋势。

| 清单列 | 推荐表达 |
| --- | --- |
| 选择框 | 首次进入全部未选中，最多选择 4 个 |
| 模型／智能体 | 连接名称，次行显示实际模型标识 |
| 系列／版本 | 已确认的系列和版本；缺失显示「未标注」 |
| 环境／用途 | 有记录时展示生产、测试或角色；未记录不推断 |
| 演练情况 | 未演练／已有结果／仅有阶段结果；显示演练次数 |
| 最近有效结果 | 最近一次有有效结果的时间和 ASR，并清楚标出对应任务；阶段结果单独标识 |
| 操作 | 演练记录、发起演练；已选对象可更换对比记录 |

未演练行显示「尚未演练」、演练次数 0、ASR `--`，提供「发起演练」。不能使用 0% 代替没有结果，也不从其他同名模型借用演练结果。

筛选建议：搜索模型／系列／版本，系列（默认全部）、对象类型、演练情况。连接状态和用途可放在更多筛选；运行的具体任务状态放到“选择演练记录”中，避免首页同时混入两套状态。排序可选最近接入、最近演练、名称，初始按最近接入；没有接入时间时使用名称排序，不伪造时间。

### 4.2 选择对象与开始对比是明确的两个动作

推荐流程：

1. 用户在全量清单中筛选，并勾选 2—4 个对象。
2. 底部出现固定的已选条，显示对象名称、版本、当前用于对比的演练记录；支持移除单个或清空。
3. 已有结果的对象可在已选条中预填“最新已完成演练”，但必须明示任务名和时间；这只是可修改的候选记录，不提前展示比较结论。
4. 用户可点击「更换演练」打开记录选择面板。确认每个对象的运行记录后，点击主按钮「开始对比」。
5. 展开独立的结果区域或进入对比页；保留已选对象和筛选，支持返回调整、更新对比。

0 个选择时不显示比较结果。1 个选择时按钮禁用并提示「至少选择 2 个对象」。达到 4 个时不再接受第 5 个，给出短提示。筛选变化不静默清空已选对象；已选但当前筛选隐藏的对象继续保留在已选条，并显示“部分对象不在当前筛选结果中”。

未演练对象可以加入已选条，但没有可用于结果比较的运行记录，因此阻止“开始对比”并明确指出缺哪一个对象的结果。提供「为该对象发起演练」，只打开并预填新建任务，不自动启动执行。用户仍可移除未演练对象后比较其他对象。

### 4.3 选择哪次演练

每个对象的运行选择面板显示任务名称、创建时间、任务状态、题库、具体方法、蓝队方案、裁判以及有效／计划单元数。用户可按任务名和状态筛选。

推荐顺序为：与参考对象方案一致的已完成运行 → 其他已完成运行 → 阶段结果。推荐需要有可核实的一致性依据，不能仅因为题库名字相同就标“同方案”。当前未保存的版本或参数显示「信息不足」。

默认比较已完成且存在有效判定的运行。阶段结果允许用户主动选入，但选择面板和结果页都保留「阶段结果」标识。纯异常或无有效判定的记录可查看执行数据，不能用于 ASR 优劣比较。

同版本多次演练属于另一种明确意图：在「演练记录」中选择 2—4 次运行，点击「对比所选演练」。不能点击一次“对比本版本”就替用户自动选最近 4 次。此时每列标题突出任务与时间，而不是重复显示相同版本名。

### 4.4 比较前先判断条件是否一致

结果页顶部展示一句清楚的比较条件说明，并可展开差异。核心条件对比不能只藏在底部折叠区。

| 条件 | 应比较的实际内容 |
| --- | --- |
| 题目范围 | 实际使用的题目及内容快照，不只比较题库名字、题数或题目 ID |
| 攻击方案 | 具体方法集合、方法参数、最大轮次、重试或采样策略 |
| 红队 | 攻击模型及影响生成的参数；不需要红队模型的方法允许为空 |
| 蓝队 | 模式、提示词内容、规则或护栏模型版本、输入／输出位置 |
| 裁判 | 模型、判定规则版本及影响判定的参数 |
| 运行范围 | 已完成／阶段、有效判定覆盖、异常情况 |
| 执行性质 | 模拟运行与真实运行不混合得出能力优劣结论 |

按证据分为三种表达：

- 「已记录的关键条件一致」：展示指标差异，但只说“本次运行 ASR 相差 X 个百分点”，不直接宣称能力提升或统计显著。
- 「部分条件不同」：照样可以并排查看事实，同时突出题库／方法／蓝队等差异；不标冠军、不写“更安全”。提供「使用同一方案复测」入口，进入可编辑的新建任务流程。
- 「条件信息不足」：旧记录缺少关键快照时明确写出缺项，不自动判断一致，也不悄悄选其他运行替换用户选择。

模型版本是用户要比较的对象差异，不应被当作阻止比较的条件。相同系列也不是可比性的充分条件，跨系列在测试方案一致时同样可以比较。

现有快照可支撑一部分严格匹配，但还缺少统一的题库／分类／规则不可变版本和部分运行参数。下一阶段可在启动时保存方案指纹及各项快照版本；它来自规范化后的实际配置，而非页面名称。

### 4.5 比较结果与下钻

结果页以 2—4 列比较表呈现，列头写清对象、版本、任务、时间和状态。上方保留「调整对象」「更换演练」「更新对比」。改了选择之后显示“选择已变更，点击更新对比”，不让已展示结果静默改变。

核心结果比较：ASR、有效／计划、攻破、守住、异常、涉及攻破题目。所有百分比同时给出分子／分母，避免 1/2 与 100/200 看起来具有相同证据量。可以由用户设定参考对象，差值使用百分点；没有参考对象时只并列结果，不预设谁是基线。

下方按需展开具体方法表现。只有题目关联和测试方法可匹配时，才进一步展示「同题结果变化」；否则说明无法做逐题对照。已有原始分类可展示，但跨题库未映射的分类不能强行放在同一风险维度上。

点击攻破／异常数进入相应任务的已筛选记录；点击任务名称进入任务详情；点击「报告」进入该次正式报告。返回比较时保留对象、运行和滚动位置，形成“看到差异 → 定位记录 → 检查证据 → 返回比较”的连贯流程。

## 五、最小数据调整与边界

版本页清单的数据起点应改为已接入资产，再左关联历史任务，不能继续从任务反推出所有资产。需要稳定的资产／版本身份；不要仅以系列文字和版本文字为唯一键，因为不同连接或环境可能使用相同标签。

短期可以使用连接 ID 关联任务，并保留任务创建时的版本快照。没有明确版本的资产仍显示为「未标注版本」；模型名称解析只用作待确认的输入建议，不自动视为已确认版本事实。历史任务的身份与结果不随当前连接改名而改变。已退役连接的历史报告应可追溯，默认清单可通过“包含历史资产”查看。

建议分两步实施：先完成全量平铺、无预选、明确开始对比、显式选择运行和条件差异提示；再补版本档案、不可变方案版本、同题对照与同方案趋势。正式报告则沿用现有统一聚合，先整理章节、证据索引和导出内容，再补标签／规则／复核字段以提升分析深度。

## 六、后续实施验收要点

- 新接入但从未演练的模型立即出现在版本清单，指标显示缺数据而非 0。
- 首次进入没有预选系列或对比对象；2—4 个对象且运行记录齐备后才可开始结果对比。
- 对比列能够说清“哪个资产版本、哪次演练、什么条件”，不只显示模型名字和 ASR。
- 同系列不同方案、跨系列相同方案、历史字段缺失、阶段结果、全异常均有准确说明。
- 核心发现的每一个数字可回到统计口径，每一个重点判断可定位到证据或标明依据不足。
- 正式报告与任务概览有清楚分工；导出后的报告能独立阅读，节选证据与完整索引标注明确。
- 没有分类不生成场景风险结论；没有复核不写已确认漏洞；没有同条件复测不宣称修复有效。
