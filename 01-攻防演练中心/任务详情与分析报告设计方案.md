# 任务详情与分析报告设计方案

本方案回应 2026-09-28 页面标注中的状态归类与报告结构问题。经选择，界面调整、四组状态筛选及第一阶段概览已实施；第二、三阶段标签治理及复测能力仍为设计方案。

## 1. 状态分组

任务列表采用四个筛选选项，具体状态仍在每行显示。

| 筛选 | 包含状态 | 含义 |
| --- | --- | --- |
| 全部 | 所有状态 | 默认入口 |
| 未结束 | 进行中、已暂停 | 仍可继续执行 |
| 已结束 | 已完成、手动结束 | 正常跑完或由用户提前结束 |
| 异常 | 任务异常 | 任务级执行失败 |

“手动结束”替换原具体状态“已结束”，避免与筛选分组重名。单条测试执行异常不是任务异常：任务正常跑完也可能存在个别调用失败，这些记录单列且不计入 ASR 分母。

## 2. 当前数据能支持什么

攻击方法和风险类别必须分开。PAIR、角色扮演、编码变换说明“怎么攻击”；违法犯罪、隐私泄露等说明“测什么风险”；客服、金融等业务场景可另设可选维度。

当前任务保存了方法、题目 ID、题库快照、攻击及响应、裁判结果和执行事件，因此可以计算方法表现、去重题目、异常与完成率，也可以从失败记录进入证据明细。

实际题库情况：

- AdvBench 共 520 题，目前只有 ID 和问题文本，没有风险分类。
- SALAD-Bench 已接入 1000 题，全部包含 category，已有 66 个细分类别。可以映射至统一风险类目，无需全部重新打标。
- 题目导入目前支持 category、target、source。新增字段需同步扩展导入、导出和快照，避免字段丢失。

当前报告的几处语义问题：

- t.scenes/u.scene 实际是攻击方法族，不是内容风险场景。仅将标题替换为“攻击方法”也不够：同一族下三种具体方法仍可能被算作一种。
- 现有单组“场景风险趋势”用补出的数据点绘线，并非时间趋势。应删除；有真实可比的时间或版本序列后才展示趋势。
- A/B/C 评级只有 ASR 阈值，缺少覆盖范围、风险严重度和正式标准，不宜称为模型整体安全等级。
- “已攻破 5”是五条攻破记录，不一定是五个不同风险：同一题被多种方法攻破会重复计数。
- 现有建议是固定文案，不能代表本次分析。所有演练结果仍为 Demo 模拟结果。

## 3. 任务详情：首屏看懂、证据可追溯

推荐顺序：

1. 任务名称＋具体状态。创建时间作为辅助信息，内部任务 ID 不占用标题区。
2. 紧凑配置：靶标、红队方法与模型、蓝队防守、裁判与题库；展示任务创建时的快照。
3. 一行核心数据：完成进度、有效判定、ASR、攻破记录／去重风险题目、执行异常。避免重复展示 ASR 及其互补值占用大片面积。
4. 核心发现 2–3 条：发生了什么、涉及哪些题目或方法、证据可信度如何。每条可展开对应攻防记录。
5. 下一步行动：优先复核哪些失败证据、补测哪些缺口、调整什么防守并用哪个回归集复测。
6. 下方分为“任务概览 / 攻防记录 / 分析报告”。执行中的任务保留演练视图入口，动画用于观察执行过程。

例如，当前 24 条测试、23 条有效判定、5 条攻破、1 条异常，应表达为“5 条攻破记录，ASR 21.7%（5/23），1 条执行异常待重试”；去重题目数量需要实际按 questionId 计算，不能直接写成 5 个风险。

## 4. 分析报告结构

| 模块 | 要回答的问题 | 数据要求 |
| --- | --- | --- |
| 测试范围与结论 | 测了谁、测了什么、结果能说明什么 | 配置快照、题目范围、方法、有效样本、标签覆盖率 |
| 核心风险分布 | 哪类内容风险最集中 | 标准风险类目；显示攻破数/有效判定数和去重题目数 |
| 攻击方法表现 | 哪种手段更容易突破防守 | 按具体 method 统计，不按方法族冒充具体方法 |
| 重点风险证据 | 为什么判为风险 | 原题、攻击方法与轮次、响应片段、命中规则、裁判依据、复核状态 |
| 修复建议与复测 | 先做什么，如何判断有效 | 每条建议关联风险证据；具体措施、优先级、复测样本和验收标准 |
| 覆盖缺口与异常 | 哪些尚未测到或无法判断 | 未执行、异常、未分类、样本不足、未经复核项 |

“风险类别 × 攻击方法”矩阵放在第二阶段：数据足够时才有信息量。未测试显示“未测试”，无有效判定显示“无有效样本”；两者都不能用 0% 表示安全。

## 5. 最小信息补全

| 对象 | 新增／规范字段 |
| --- | --- |
| 题目 | riskCategoryId、riskSubcategoryId、expectedSafeBehavior、rubricId；businessContext 可选 |
| 分类元信息 | 原始分类、分类版本、来源（原生/规则/模型/人工）、模型建议置信度、人工确认状态 |
| 判定 | violatedRuleIds、evidenceSpans、reason、reviewStatus；严重度须按规则与影响判定 |
| 任务快照 | 题库版本、题目/标签快照、分类体系版本、裁判与判定规则版本 |

一级、二级主类目用于可加总的统计；辅助标签可多选，但报告需提示多标签统计可能重复。标签缺失保留“待分类”，低置信度或未经确认的标签不能写成确定结论。

自动打标可按“模型建议 → 人工抽检／高风险重点复核 → 固化版本”实施。题目风险类目表示测试意图，实际违规类别仍需裁判依据响应证据判定，不能看到题目标签就认定模型发生该风险。

## 6. 分阶段交付

第一阶段（已实施）：无需新增标签。去除无依据的趋势和评级；按具体方法统计；补充去重涉及题目、核心证据摘要及异常/覆盖缺口；建议仅基于已有记录。缺少题目 ID 时不假定每条记录都是独立题目。

第二阶段：统一 SALAD 标签，补齐 AdvBench 标签、预期安全行为和判定规则；支持分类分布、复核状态、风险建议与固定回归集。

第三阶段：积累同一测试范围和裁判标准下的多次结果，提供版本对比、真实趋势、修复前后变化和复测闭环。范围不一致时提示不可直接比较。

网页概览和 HTML/PDF/Word 导出应共用同一份结构化报告数据，避免页面展示和导出结论不一致。
